# 22-接口设计规范

> **本文件规定涉及接口（API）开发时的设计要求。核心规则：改接口必先改 T5 文档。**

- 版本：v1.11
- 前置阅读：`00-总则.md`、T3

---

## 一、硬性规则

1. **文档先行**：接口的新增、参数变更、响应变更，必须先更新 T5 接口设计文档，确认后再改代码；
2. **接口变更需评估调用方**：修改已有接口前，列出所有调用方（前端页面/其他服务/第三方），评估影响；
3. **不破坏性修改**：能加参数不删参数，能向后兼容不做破坏性变更；确需破坏性变更 → 走《30-变更控制规范》并同步所有调用方。
4. **前后端权限源同源（禁止前端写死权限假设）**：前端菜单可见性、按钮可点击性，必须由「与后端 enforcement 同一份权限集」驱动——用户登录后由后端下发其角色/权限集，前端据此渲染与拦截；禁止在前端代码里写死「某角色能用某功能」的假设。角色×接口权限矩阵为单一真相源，前后端均从同一份定义生成，从根上消除「前端显示能做、一点就 403」的权限漂移。

## 二、设计要求

- **URL 规范**：【项目风格填空位：RESTful / 自定义】。资源用名词、操作用方法；URL 全小写；
- **方法语义**：GET 查询（无副作用）、POST 新增、PUT/PATCH 更新、DELETE 删除；
- **统一响应结构**：【项目约定填空位，示例：
  ```json
  { "code": 0, "message": "ok", "data": { } }
  ```
  code=0 成功，非 0 见错误码表】
- **鉴权与访问控制（设计阶段即前置）**：每个接口必须标注鉴权要求（免登/登录/指定角色）；涉及数据的接口默认按"需登录 + 最小角色"设计，开放免登接口须显式说明理由；访问控制遵循 **默认拒绝（deny-by-default）**——未显式授权的访问一律拒绝，**完全仲裁（complete mediation）**——每次请求都做鉴权判断（不无限缓存鉴权结果）；越权风险（横向/纵向）在设计时即评估，并产出**角色×接口权限矩阵**逐格验证（呼应红线 R10–R13、呼应《20》三权分立 + 职责分离）；**admin/超级管理员例外**：超级管理员作为矩阵的全局例外，拥有全部接口权限、可绕过逐格鉴权（但仍须通过认证）；矩阵中以 `admin` 全通标注，前端对 super-admin 直接视为全权限，避免「admin 反而被 403」的同源断裂——即同源规则不排除超级管理员，仅排除「前端私自假设权限」。
- **输入校验契约**：每个参数写明类型、边界、取值范围、超长/非法处理（拒绝 or 截断）；把校验规则写进 T5，使编码阶段有契约可依，避免"后面再测"；
- **限流与防爬**：列表/导出/高频接口在设计时即注明频控与单次量上限（防批量拉取，呼应《26》H6）；
- **错误信息不泄露内部细节**：统一错误结构只对外暴露安全错误码与提示，堆栈/SQL/路径由统一层收敛（呼应《23》异常处理纪律）；
- **分页**：列表接口统一分页参数（如 `page`、`page_size`，默认值写明）；
- **CORS 来源白名单（前后端分离必填）**：设计阶段即定义允许的跨域来源（开发态 `http://localhost:xxxx` 与生产域分别列出），**严禁 `*` 通配**；涉及凭证（cookie）时来源须精确匹配、不得带 `*`；来源与《27》部署形态（同域 `/admin` 子路径或子域）一致；
- **性能设计前置**：列表/导出/统计类接口在设计时即预估数据量级，决定同步分页（限定每页上限与超时）还是异步任务（超限必须异步，禁止一次返回全量）；高频读/重聚合标注缓存策略，避免实时重算；量级与方案写进 T5，编码只实现不临时决策（呼应《20》性能设计项）。
- **错误码**：新增错误码必须登记到错误码表，含义唯一。

## 三、T5 接口设计文档模板

保存至：`docs/tech/T5-接口设计-<模块名>.md`

```markdown
# T5-接口设计-<模块名>

版本 / 日期 / 状态
关联功能：F00x

## 1. 接口清单
| 编号 | 方法 | 路径 | 用途 | 鉴权 |
|------|------|------|------|------|
| API-001 | GET | /api/v1/assets | 资产列表查询 | 登录 |

## 2. 接口明细
### API-001 资产列表查询
**用途**：<一句话>

请求参数：
| 参数 | 位置 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| keyword | query | string | N | 名称模糊搜索 |
| page | query | int | N | 页码，默认 1 |

响应：
| 字段 | 类型 | 说明 |
|------|------|------|
| data.list | array | 资产数组 |
| data.total | int | 总条数 |

错误码：
| code | 含义 | 触发场景 |
|------|------|---------|
| 40001 | 参数非法 | keyword 超长 |

```

## 四、准出检查

- [ ] 每个接口都有：用途、鉴权、请求参数、响应结构、错误码？
- [ ] 每个参数都写了类型/边界/非法处理（输入校验契约）？
- [ ] 列表/导出/高频接口已注频控与单次量上限？
- [ ] 接口与 T3 的模块设计一致（含安全需求项）？
- [ ] 修改已有接口时已列出调用方并评估影响？
- [ ] 新增错误码已登记？
- [ ] 大数据量接口已定同步分页 or 异步任务方案，量级预估已写进 T5？
- [ ] 前后端分离项目已定义 CORS 允许来源白名单（开发/生产分别，禁止 `*`）？
- [ ] 前后端权限源同源已落实：前端权限由后端下发的权限集/角色驱动，无前端写死假设；超级管理员（admin）已作为矩阵全局例外、可全通（但仍需认证）？
