# 27-部署管理规范 —— 项目部署与环境文档

> **本文件规定项目实际部署的文档要求。核心规则：项目首次可部署时必须产出部署文档（T11），此后每次部署/上线都要更新部署记录；环境信息只在此文档维护，禁止散落在对话记录里。**
>
> 与《25-上线方案规范》的分工：**25 管"某次变更怎么发布"（变更视角，一次性）；本规范管"项目怎么部署、环境长什么样"（环境视角，持续维护）**。T7 上线方案中的部署步骤必须与 T11 部署文档中的环境信息一致，不一致时以 T11 为准并先修正。

- 版本：v1.6
- 前置阅读：`00-总则.md`、`25-上线方案规范.md`
- 产出文档：T11 部署文档（保存至 `docs/deploy/T11-部署文档.md`，全项目一份持续维护）

---

## 一、部署文档的触发时机

| 时机 | 动作 |
|------|------|
| 项目首次在任意环境可运行 | 创建 T11 部署文档（完整版） |
| 新增部署环境（如新增预发环境） | T11 增加"环境信息"一节 |
| 架构变化（新增服务/中间件/域名变更） | **先更新 T11 再执行部署**（文档先行，同 T4/T5 规则） |
| 每次部署/上线 | 更新 T11 的"部署记录"表（与 T7、CHANGELOG 关联） |
| 环境配置变更（端口、环境变量、证书） | 更新 T11 对应环境小节 + CHANGELOG |
| 接手已运行项目且无 T11 | 按现状反向补建 T11（同首次创建，但环境信息以实际运行为准，禁止凭记忆编造） |

**禁止**：部署做完不记文档——下次部署就只能靠翻聊天记录和猜。

## 三、部署执行纪律

1. **部署前**：环境信息核对 T11；涉及架构/配置变更的，T11 已先行更新；
2. **部署中**：按 T7 上线方案步骤执行（功能发布）或 T11 第 6 节标准手册执行（环境重建/常规更新），每步验证；
3. **部署后**：健康检查 + 按 T1 验收标准线上验证；**部署记录追加到 T11 第 9 节**——失败和回滚也要如实记；
4. **部署失败**：按 T7 回滚方案处理，处理完在 T11 部署记录和 CHANGELOG 双记录，并补充"常见故障"条目。

### 成本、凭据与备份隔离（硬约束）

- **成本与配额**：对外暴露的接口必须限速 + 配额 + 成本告警；部署/对外服务前设预算上限与硬限，避免无限速导致账单爆炸（如无限 spawn、无节流）；
- **凭据最小权限**：AI 代理/部署动作只持最小权限、短时、作用域限定的令牌；生产凭据隔离存放，绝不持跨环境 blanket 权限；凭据卫生优先于功能速度；
- **备份隔离**：数据库/关键数据备份必须独立存储，不可经与生产数据同一身份删除；备份与生产分置，定期恢复演练并记录。

## 四、AI 执行部署任务的行为边界

1. **生产环境操作前必须获用户明确确认**——部署、重启、迁移、配置修改均属外部高危动作，先列出"将要执行的操作清单+影响"，确认后执行；
2. 敏感信息不落明文（文档、对话、代码仓库都不行），只记录存放位置与获取方式；
3. 无法完成的环境操作（无服务器权限、需人工审批）→ 在 T11 中标注"需人工执行"并写明步骤，不假装已执行；
4. 部署结果如实记录：失败就是失败，回滚就是回滚，禁止报喜不报忧。
