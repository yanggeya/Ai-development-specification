# T2-功能清单模板

> 使用说明：这是全项目功能的**唯一登记台账**。每个功能分配全项目唯一编号（F001 起，永不复用），后续开发、变更、功能说明文档（T8）都以此编号为锚点。保存至 `docs/requirements/T2-功能清单-<项目名>.md`。
>
> 配套文档：**T9 功能树**（`docs/功能树.md`）——本清单是台账（每功能一行），功能树是结构（层级与依赖）。两者必须同步维护：登记/变更任何功能时，清单与功能树一起更新。
>
> **本清单同时承担「全项目功能与要求概览」职责**：除编号/状态等元数据外，每个功能须填「功能要求摘要」与「核心验收点」，使整个项目的功能及要求在一张表完整可见，不必逐份打开 T8 也能纵览全局。

## 字段说明

- **功能编号**：F + 三位数字，全项目唯一，分配后即使功能废弃也不回收；
- **优先级**：P0（必须有）/ P1（重要）/ P2（增强）；
- **状态**：待开发 → 开发中 → 已上线 → （变更中 → 已上线）；功能废弃标记「已废弃」并保留行，禁止删除；
- **功能要求摘要**：一句话说清该功能解决什么问题、覆盖什么场景（非详细设计，详细见 T8）；**要求非空**——空 = 需求未完善，不得冻结；
- **核心验收点**：1~2 条可验证的验收标准（给输入/操作能明确判对错），与 T1 第 3 节该功能的验收标准对齐（详细验收在 T8）；**要求非空**——空 = 不可验收；
- **功能说明文档**：功能开发完成时按 T8 模板创建，与功能编号一一对应；
- **最近变更**：日期 + 一句话（走《30-变更控制规范》后更新）。

## 维护规则

1. 新增功能：需求确认时登记；变更控制流程中新增的功能也必须回到本清单登记；
2. 状态流转：每次开发/变更完成时同步更新状态列；
3. 本清单是 AI 判断「接到修改指令时该读哪份功能说明文档」的检索入口；
4. **功能树同步义务**：新增/拆分/合并/废弃功能时，同步更新 T9 功能树（含依赖关系表）；改台账不改功能树 = 任务未完成。

## 全局功能覆盖自检（登记 / 冻结前必做）

每次新增 / 变更功能、或需求冻结前，按此清单自检；**任一不过 = T2 未完善，不得进入设计 / 编码**：

- [ ] **无遗漏**：T2 每个功能对应 T1 第 3 节一个功能需求，T1 列的功能在 T2 均有登记（双向一致）；
- [ ] **无超范围**：T2 无 T1 未包含的功能（临时加的需求须先回 T1 或走《30-变更控制规范》）；
- [ ] **摘要非空**：每个功能「功能要求摘要」已填，能一句话说清解决什么问题；
- [ ] **验收可验证**：每个功能「核心验收点」已填，给输入 / 操作能明确判对错；
- [ ] **优先级齐全**：每个功能优先级已标（P0/P1/P2），无空白；
- [ ] **范围外清晰**：T1 第 6 节「范围外事项」已列，无含糊的"以后可能做"；
- [ ] **开放问题已决**：T1 第 7 节「开放问题」每项已决策或标注待定，无悬空。
