# 接手冲突核对与解决记录 —— T-接手冲突（模板）

> 接手既有项目时，实际代码与已有文档（需求/设计/README）出现实质不一致，一律登记进本文档，**不得只停留在对话或报告里**。
> 每条冲突必须同时具备「冲突登记」与「解决记录」两部分，缺一视为接手未完成。撰写要求见《12-接手既有项目规范》总原则 8。
> 本文件随项目走，放在 `docs/接手冲突核对与解决记录.md`（非 ai-dev-guide/ 内）。

---

## 一、冲突登记（盘点阶段填写）

逐条记录"文档说 A、代码实际做 B"的不一致项。冲突类型填：需求 / 接口 / 数据结构 / 行为逻辑 / 配置 / 其他。

| 编号 | 冲突类型 | 涉及功能/模块 | 文档说法（出处） | 代码实际（实证位置） | 发现日期 | 状态 |
|------|---------|--------------|----------------|---------------------|---------|------|
| C001 | 【类型】 | Fxxx / 模块名 | 文档/README 写的是……（引文件名+章节） | 实际代码在 `<文件:行>` 做的是…… | YYYY-MM-DD | 待裁定 |
| C002 | | | | | | 待裁定 |

> 状态：待裁定 → 已裁定（以代码） / 已裁定（以文档） / 待确认（仍无法核实）

## 二、解决记录（用户裁定后逐条补全）

每条冲突对应一条解决记录：裁定结论、裁定人、日期、处置动作、关联文件。

### C001
- **裁定结论**：以代码为准 / 以文档为准 / 维持现状（标注原因）
- **裁定人**：<用户名>（注：以文档为准时，代码视为偏离，记入待修复清单，此处不改代码）
