# 24-测试与验收规范

> **本文件规定开发完成后的测试与验收要求。核心：测试用例必须回溯 T1 验收标准，验收以文档为准。**

- 版本：v1.11
- 前置阅读：`00-总则.md`、T1

---

## 一、测试设计原则

1. **验收标准即测试用例来源**：T1 中每条验收标准至少对应一个测试用例；文档没提的行为不是验收对象；
2. **覆盖三类路径**：正常路径、边界条件（空/超长/极值）、异常路径（非法输入/无权限/依赖失败）；
3. **数据变更类功能必须测回滚**：验证上线方案中的回滚方式真实可行。
4. **测试要精简、求有效**：以"抓住真实缺陷"为目标，不为达标堆砌无意义用例；优先覆盖高风险路径，避免重复/冗余、仅证明已知正常的用例。
5. **前端功能自测（含网站/后台前端项目）**：除后端接口自测外，必须按 T1 验收标准逐条过一遍主流程页面交互——路由跳转与路由守卫（公开 vs 登录 vs 仅管理员）、表单提交与校验提示、登录态保持与登出、列表/分页/搜索实际渲染；**不得只验证后端 API 通就算完成**，禁止把前端自测结果混写为后端接口测试（映射见《23》）；前后端联调（后端起服、前端调真实接口验字段/鉴权/CORS）作为本环节必要步骤。

## 二、测试执行要求

| 级别 | 要求 |
|------|------|
| P1 重大功能 | 完整测试记录（T6），含正常/边界/异常用例及结果 |
| P2 一般功能 | 简版测试记录：核心路径 + 关键边界用例 |
| P3 小改动 | 验证修复点 + 抽查相邻功能未受影响 |

### 测试纪律（门禁、断言有效性、覆盖维度）

- **测试门禁配置锁定**：覆盖率阈值、lint 规则、测试命令由人类在配置中锁定；**禁止 AI 自降阈值、修改 CI 测试配置或以 build-tag 假实现绕过**自己建的 anti-mock 规则（违反即视为伪造，触犯红线 R17）。覆盖率只是"下限"。
- **无 CI 前置（缺口 F11）**：若项目尚未配置任何 CI / 测试门禁，AI 在交付前应先建立**最小门禁**（最基础测试脚本或最简 CI 配置），使"测试必须通过"真实被卡住，而非在裸环境自我证明"已通过"；最小门禁同样适用上一条锁定规则，禁止后续自降；**变更管控**：建立最小门禁、测试脚本、CI 配置文件属于对项目的改动，须走《30-变更控制规范》的 P3 简化流程（说明现象/方案 + 打基线锚点 + 记入 CHANGELOG），禁止无记录直接进仓库。
- **深度 CI/CD 集成（可选）**：当 `docs/tech/技术栈约定.md` §8 声明启用"CI/CD 强验证"时，最小门禁升级为多阶段管线 + 合并/发布闸门，具体要求见《29-持续集成与自动化验证规范》（按项目可选，未启用不强制）。
- **断言须独立有效**：断言必须基于独立预期（数学关系、多组输入对照），**禁止 mock 返回值循环自洽断言**；每个用例必须有真实断言，禁止将结果赋给空白标识符 `_` 或仅 `t.Log()` 伪装断言。
- **覆盖维度**：强制分支/边界覆盖（错误路径、边界、外部调用失败），仅看行覆盖会漏掉真实故障；对关键外部契约/字段做 schema/契约测试，防止底层模型或依赖更新导致的"字段静默漂移"。
- 鼓励变异测试（mutation testing）验证测试是否真能抓住缺陷。
- **测试完成后清理多余文件**：测试过程产生的临时/中间产物（覆盖率报告临时文件、测试生成的 dump/日志/截图、调试用临时脚本）应在测试结束后删除，保持仓库干净；**禁止删除测试代码、测试文档、必要 fixtures 与 T6 测试记录**（属项目资产）。清理动作本身不得影响测试结论与可复现性。

## 三、自动化测试（如项目采用）

- 测试代码位置：【项目约定填空位：`______`（见 `docs/tech/技术栈约定.md`，由 AI 接入时与用户确认后写入）】；
- 新功能的核心业务规则应有单元测试；测试用例名与功能编号关联（如 `test_F003_status_flow`）；
- 回归：改动后运行既有测试，全绿才可提交。

保存至：`docs/test/T6-测试记录-<功能名>-<日期>.md`（与总则/26 的 `docs/test/` 一致；P2/P3 可直接记录在 CHANGELOG 条目中）

| 1 | <T1 验收标准 1> | | | | ✅/❌ |

## 缺陷记录

|---|------|------|------|

【是否达到验收标准，可否进入上线流程】

## 五、准出检查

- [ ] T1 每条验收标准都有用例且通过？
- [ ] 边界与异常路径已覆盖？
- [ ] 缺陷已修复或已明确记录遗留？
- [ ] 回滚方案验证过（涉及数据变更时）？
- [ ] 含前端项目已按 T1 验收标准自测主流程页面交互（路由/表单/登录态/列表渲染）且前后端已联调？

**功能测试通过 ≠ 可以上线**。准出后进入下一道门：《26-安全测试规范》——安全测试通过并出具 T10 报告后，才可进入上线流程（25）。
